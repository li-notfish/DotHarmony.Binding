# API 绑定 .NET 风格标准化（两阶段 + 运行时整治，破坏性改名）

范围已确认：机械标准化 + 接口实例包装类 + 运行时整治；直接破坏旧命名，samples 同步更新。

## 现状问题（已探明）

1. **命名**：`capitalizeFirst` 只大写首字母 → `GetURI`/`AbiList`/`MIMETYPE_TEXT_PLAIN` 等不符合 .NET 缩写词规范；Task 方法无 `Async` 后缀；枚举成员保持 SCREAMING_CASE。
2. **类型映射三处分叉**：Promise→Task 在 typeMapper.ts:273-289、astParser.ts:418-471、apiGenerator.ts:217-271 各有一份；IntPtr 回退有两份（typeMapper:121 与 apiGenerator.isUnmappedType:328）。
3. **103 个方法返回裸 IntPtr**：接口类型（Display/PasteData/HttpRequest/PixelMap…）全部退化为句柄；`Task<IntPtr[]>`（GetAllDisplay）连运行时转换都不支持（潜在坑）。
4. **on\* 误判**（astParser.ts:391/519-521）：服务模块的 `onChangeWithAttribute`、`onApplicationFocusStateChange` 被当组件事件丢弃；delegates/events 解析后从不生成（死数据）。
5. **运行时缺口**：无 JsObject 包装基类、无 SetProperty/GetGlobal、PromiseTaskBridge 与 ThreadSafeFunction.FromPromise 两套重复实现、ConvertResult 只支持 7 种基元。
6. **命名冲突事实**：d.ts 接口 `Display`/`Window`/`Sensor`/`Image` 与模块静态类同名；`Rect`/`Size` 跨模块重复；MAUI 也有 Rect/Size（samples 曾因此全限定）。

## 第一阶段：运行时基建（HarmonyOS.Bindings/Runtime）

1. **新增 `JsObject` 基类**（public）：持有 `NapiReference`（强引用）+ `IntPtr Handle`，实现 IDisposable；protected 助手 `Get<T>(name)`/`Set(name, value)`/`Call<T>(name, args)`/`CallAsync<T>(...)`。
2. **NodeApi 扩展**：`SetProperty`、`GetGlobal`、`CallMethodAsync<T>(..., Func<IntPtr,T> converter)` 重载（**转换委托在生成代码调用点显式传入**——AOT 安全、无反射、无注册表）；`CreateInstance`（napi_new_instance，供嵌套类构造）。
3. **转换能力扩充**（ConvertResult / PromiseTaskBridge）：数组（napi_get_array_length + 逐元素 + converter）、枚举（int→enum）、`long`；不可转换时抛 NotSupportedException 的清单文档化。
4. **合并重复实现**：`ThreadSafeFunction.FromPromise` 并入 `PromiseTaskBridge.ToTask<T>`，删除重复的 State/Trampoline 代码。
5. `NativeValue.From` 支持 `JsObject`（传 Handle）。

## 第二阶段：生成器改造（src/parser）

1. **命名规范化模块**（新增 `naming.ts` 或并入 typeMapper）：
   - 按 camelCase/大写连续段切词 + 缩写词表归一：URI→Uri、URL→Url、HTTP→Http、ID→Id、DNS→Dns、NFC→Nfc、GNSS→Gnss、UDID→Udid、ABI→Abi、SSID→Ssid、RSSI→Rssi、JSON→Json、XML→Xml、HTML→Html、MD5→Md5 等；两字母缩写保留大写（IP、TV、SN、AV）。示例：`getURI→GetUri`、`getDnsAscii→GetDnsAscii`、`sdkApiVersion→SdkApiVersion`。
   - Task/Task\<T\> 返回的方法自动加 `Async` 后缀（已带 Async 不重复）。
   - 枚举成员：按 `_` 切词 + 同表归一 → PascalCase（`TYPE_DEFAULT→TypeDefault`、`MIMETYPE_TEXT_PLAIN→MimeTypeTextPlain`），保留 `[Description]`（字符串枚举值）。
2. **类型映射单一事实源**：Promise/AsyncCallback 逻辑全部收口到 TypeMapper；删除 apiGenerator.isUnmappedType 第二套白名单，apiGenerator 信任 TypeMapper 产物（未知类型仍回退 IntPtr，但只此一处）。
3. **接口收集与分类**：parseNamespace 的嵌套 interface 改走 `parseInterfaceFull` 存入 ComponentInfo（新字段 `interfaces: InterfaceInfo[]`），按规则分类：
   - 有方法/函数签名 → **JsObject 派生包装类**（如 `PasteData`、`ImageSource`）：typed 属性 getter（GetProperty + NativeValue.To\*）+ 实例方法（CallMethod 于自身句柄）。
   - 纯数据且仅作入参 → **sealed record + INapiRecord**（WriteTo 序列化，NativeValue.From 已支持）。
   - 纯数据但被返回类型引用 → 也生成包装类（含属性 getter）。
   - 命名规则：包装类用接口原名；与模块静态类撞名时加 `Object` 后缀（Display→`DisplayObject`、Window→`WindowObject`）；跨模块同名（Rect/Size）沿用枚举的全局去重模式。
   - 返回接口类型的方法：`Task<DisplayObject> GetDefaultDisplayAsync()`，调用点传 `h => new DisplayObject(h)` 工厂；数组同理 `Task<DisplayObject[]>`。
4. **on\* 修复**：服务模块路径（parseNamespace→parseMethod）不再走 isEventMethod 分支，`on`/`off`/`onChangeWithAttribute` 变普通方法（callback 参数 → Action\</IntPtr\>）；组件路径行为不变。删除 events/delegates 死数据在服务路径的写入。
5. **嵌套 class 支持（修 Picker 空壳）**：parseNamespace 处理嵌套 `class` 声明（PhotoViewPicker 等）→ JsObject 包装类；有 constructor 的经 `NodeApi.CreateInstance` 构造。
6. XML 文档补全：`@since` 版本、权限摘要、ArkTSException 抛出说明。
